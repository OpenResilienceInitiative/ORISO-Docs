## Frontend-Anwendungen

### ORISO-Frontend (Benutzerportal)
- **Docker-Image:** `caritas-frontend:latest`
- **Zweck:** Zentrale Benutzeranwendung für Ratsuchende
- **Technologie:** React 19, angepasster webpack-Build, TypeScript
- **Zugriff:** https://app.example.org
- **Wichtige Funktionen:**
  - Benutzerauthentifizierung über Keycloak
  - Echtzeit-Chat über Matrix SDK
  - Videoanrufe über LiveKit/WebRTC
  - Terminplanung
  - Profilverwaltung

### ORISO-Admin (Administrationsoberfläche)
- **Docker-Image:** `caritas-admin:latest`
- **Zweck:** Verwaltungsoberfläche für Beratungsstellen und Beratende
- **Technologie:** React 19, Vite, TypeScript
- **Zugriff:** https://admin.example.org
- **Wichtige Funktionen:**
  - Beratungsstellenverwaltung
  - Benutzerverwaltung
  - Konfiguration von Beratungsarten
  - Systemadministration

## Technologiestack

### Build-Werkzeuge
- **Build-System:** Vite (ORISO-Admin) / angepasster webpack-Build (ORISO-Frontend)
- **Framework:** React 19
- **Sprache:** TypeScript
- **Paketmanager:** npm/yarn

### Wichtige Abhängigkeiten
- **Matrix SDK:** `matrix-js-sdk` für Echtzeitnachrichten
- **Keycloak JS:** `keycloak-js`-Adapter für Authentifizierung
- **WebRTC:** LiveKit SDK für Videoanrufe
- **HTTP-Client:** Axios oder fetch API

## Build-Prozess

### Entwicklungs-Build
```bash
cd caritas-workspace/ORISO-Frontend
npm install
npm run dev
```

### Produktions-Build
```bash
# Build Docker image
docker build -t caritas-frontend:latest .

# Import to k3s
sudo k3s ctr images import <(docker save caritas-frontend:latest)

# Deploy via Helm
cd caritas-workspace/ORISO-Kubernetes/helm
helm upgrade oriso-platform ./oriso-platform \
  --namespace caritas \
  -f values.yaml
```

## Umgebungsvariablen

### Variablen zur Build-Zeit
Umgebungsvariablen werden während des Builds in die Ausgabe integriert (nicht zur Laufzeit):

```bash
# .env file
VITE_API_URL=https://api.example.org
VITE_KEYCLOAK_URL=https://auth.example.org
VITE_KEYCLOAK_REALM=online-beratung
VITE_KEYCLOAK_CLIENT_ID=app
VITE_MATRIX_HOMESERVER_URL=https://matrix.example.org
VITE_MATRIX_SERVER_NAME=caritas.local
VITE_LIVEKIT_URL=wss://livekit.example.org
```

### Docker Build
```dockerfile
# Dockerfile
FROM node:18-alpine AS builder
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
ARG VITE_API_URL
ARG VITE_KEYCLOAK_URL
ENV VITE_API_URL=$VITE_API_URL
ENV VITE_KEYCLOAK_URL=$VITE_KEYCLOAK_URL
RUN npm run build

FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html
```

## Matrix-SDK-Integration

**Speicherort:** `src/services/matrixClientService.ts`

**Funktionen:**

- Erstellung und Verwaltung von Räumen

### Matrix-Anrufdienst
**Speicherort:** `src/services/matrixCallService.ts`

**Funktionen:**
- Starten von WebRTC-Anrufen
- Verwaltung des Anrufzustands
- LiveKit-Integration für Gruppenanrufe
- UI-Komponenten für Anrufe

### Brücke für Matrix-Live-Ereignisse
**Speicherort:** `src/services/matrixLiveEventBridge.ts`

**Funktionen:**
- Echtzeitsynchronisierung von Ereignissen
- Nachrichtenbenachrichtigungen
- Aktualisierung des Anwesenheitsstatus
- Tippindikatoren

## Keycloak-Integration

### Keycloak-JS-Adapter
**Speicherort:** `src/services/keycloakService.ts`

**Konfiguration:**
```typescript
import Keycloak from 'keycloak-js';

const keycloak = new Keycloak({
  url: import.meta.env.VITE_KEYCLOAK_URL,
  realm: import.meta.env.VITE_KEYCLOAK_REALM,
  clientId: import.meta.env.VITE_KEYCLOAK_CLIENT_ID,
});

await keycloak.init({
  onLoad: 'check-sso',
  checkLoginIframe: false,
});
```

### Authentifizierungsablauf
1. Benutzer öffnet das Frontend.
2. Keycloak-JS-Adapter prüft auf eine bestehende Sitzung.
3. Ohne Sitzung erfolgt die Weiterleitung zur Keycloak-Anmeldung.
4. Nach der Anmeldung werden JWT-Tokens empfangen.
5. Tokens werden in API-Anfragen mitgesendet.

## Bereitstellung

### Kubernetes-Bereitstellung
Frontend-Anwendungen werden über Helm bereitgestellt:

```yaml
# Helm values.yaml
frontend:
  enabled: true
  image:
    repository: caritas-frontend
    tag: latest
  ingress:
    enabled: true
    host: app.example.org
```

### Ingress-Konfiguration
```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: frontend-ingress
  namespace: caritas
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt-prod
spec:
  tls:
  - hosts:
    - app.example.org
    secretName: frontend-tls
  rules:
  - host: app.example.org
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: oriso-platform-frontend
            port:
              number: 80
```

```typescript
const client = createClient({
  baseUrl: import.meta.env.VITE_MATRIX_HOMESERVER_URL,
  userId: '@user:caritas.local',
  accessToken: matrixAccessToken,

await client.startClient();
```

## Überwachung

### Zustandsprüfungen
Frontend-Anwendungen liefern statische Dateien über Nginx aus. Die Zustandsprüfungen überprüfen:
- Nginx läuft.
- Statische Dateien sind erreichbar.
- Ingress-Routing funktioniert.

### Fehlererfassung
Erwägen Sie die Integration von:
- Sentry zur Fehlererfassung
- Google Analytics für Nutzungsmetriken
- Eigenen Analyse-Endpunkten

## Fehlerbehebung

### Build-Probleme
```bash
# Clear node_modules and reinstall
rm -rf node_modules package-lock.json
npm install

# Clear Vite cache
rm -rf node_modules/.vite
```

### Laufzeitprobleme
```bash
# Check pod logs
kubectl logs -n caritas deployment/oriso-platform-frontend

# Verify environment variables
kubectl exec -n caritas deployment/oriso-platform-frontend -- env | grep VITE

# Test ingress
curl -I https://app.example.org
```

### Probleme mit der Matrix-Verbindung
1. Prüfen Sie, ob die Matrix-Homeserver-URL korrekt ist.
2. Prüfen Sie die CORS-Einstellungen in Matrix Synapse.
3. Prüfen Sie die Matrix-Zugangsdaten im localStorage.
4. Prüfen Sie die Browserkonsole auf Fehler.
