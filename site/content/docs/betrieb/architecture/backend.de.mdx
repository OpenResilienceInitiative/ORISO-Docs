## Dienstdetails

### TenantService
- **Port:** 8081
- **Zweck:** Mandantenverwaltung
- **Datenbank:** MariaDB (Datenbank tenantservice)
- **Technologie:** Spring Boot 2.7.14, Java 17
- **Dienstname:** `oriso-platform-tenantservice.caritas.svc.cluster.local:8081`
- **Zustandsendpunkt:** `/actuator/health`

### UserService
- **Port:** 8082
- **Zweck:** Benutzerverwaltung, Authentifizierung, Profile, Matrix-Integration
- **Datenbank:** MariaDB (Datenbank userservice)
- **Technologie:** Spring Boot 2.7.14, Java 17
- **Dienstname:** `oriso-platform-userservice.caritas.svc.cluster.local:8082`
- **Zustandsendpunkt:** `/actuator/health`
- **Besondere Funktionen:** Erstellung von Matrix-Benutzern, Raumverwaltung

### ConsultingTypeService
- **Port:** 8083
- **Zweck:** Verwaltung von Beratungsarten
- **Datenbank:** MariaDB (Datenbank consultingtypeservice) + MongoDB (Collection consulting_types)
- **Technologie:** Spring Boot 2.7.14, Java 17
- **Dienstname:** `oriso-platform-consultingtypeservice.caritas.svc.cluster.local:8083`
- **Zustandsendpunkt:** `/actuator/health`

### AgencyService
- **Port:** 8084
- **Zweck:** Verwaltung von Beratungsstellen und Administration
- **Datenbank:** MariaDB (Datenbank agencyservice)
- **Technologie:** Spring Boot 2.7.14, Java 17
- **Dienstname:** `oriso-platform-agencyservice.caritas.svc.cluster.local:8084`
- **Zustandsendpunkt:** `/actuator/health`

## Technologiestack

### Gemeinsamer Stack
- **Framework:** Spring Boot 2.7.14
- **Java-Version:** 17
- **Build-Werkzeug:** Maven
- **Datenbankmigration:** Liquibase **DEAKTIVIERT** (Schemata werden in ORISO-Database verwaltet)

### Datenbankverbindungen
Alle Dienste verbinden sich über Kubernetes ClusterIP mit MariaDB:
```
jdbc:mariadb://oriso-platform-mariadb.caritas.svc.cluster.local:3306/<database-name>
```

### Kommunikation zwischen Diensten
Dienste kommunizieren über Kubernetes-DNS mit REST:
```
http://oriso-platform-<service-name>.caritas.svc.cluster.local:<port>
```

## Verwaltung der Datenbankschemata

### Liquibase-Status
**Liquibase ist in allen Diensten DEAKTIVIERT.** Die Datenbankschemata werden zentral im Repository ORISO-Database verwaltet.

### Speicherort der Schemata
- **Repository:** `caritas-workspace/ORISO-Database`
- **MariaDB-Schemata:** `mariadb/*/schema.sql`
- **MongoDB-Schemata:** `mongodb/consulting_types/`
- **Einrichtungsskript:** `scripts/setup/00-master-setup.sh`

### Schemaaktualisierungen
1. Aktualisieren Sie die Schemadateien im Repository ORISO-Database.
2. Führen Sie die Migrationsskripte manuell aus.
3. Dienste führen beim Start KEINE automatische Migration aus.

## Zustandsprüfungen


## Bereitstellung

### Helm-Bereitstellung
Alle Backend-Dienste werden über das übergeordnete Helm-Chart `oriso-platform` bereitgestellt:

```bash
cd caritas-workspace/ORISO-Kubernetes/helm
helm install oriso-platform ./oriso-platform \
  --namespace caritas \
  --create-namespace \
  -f values.yaml
```

### Bereitstellung einzelner Dienste
Dienste können einzeln aktualisiert werden:

```bash
helm upgrade oriso-platform ./oriso-platform \
  --namespace caritas \
  -f values.yaml \
  --set userservice.enabled=true
```

## Konfiguration

### Umgebungsvariablen
Dienste werden über Kubernetes ConfigMaps und Secrets konfiguriert:

```yaml
env:
  - name: SPRING_DATASOURCE_URL
    value: jdbc:mariadb://oriso-platform-mariadb.caritas.svc.cluster.local:3306/userservice
  - name: SPRING_DATASOURCE_USERNAME
    valueFrom:
      secretKeyRef:
        name: mariadb-secrets
        key: MYSQL_USER
  - name: KEYCLOAK_URL
    value: http://oriso-platform-keycloak.caritas.svc.cluster.local:8080
```

### Diensterkennung
Alle Dienst-URLs verwenden Kubernetes-DNS:
- Keine fest eingetragenen IPs
- Automatische DNS-Auflösung
- Lastverteilung über Kubernetes-Service-Proxy

## Überwachung

### Health Dashboard
Alle Dienste werden vom Health Dashboard überwacht:
- **URL:** http://YOUR_SERVER_IP:9001
- **Prüfungen:** Alle 60 Sekunden
- **Endpunkte:** `/actuator/health`

### SignOZ-Integration
Dienste können mit OpenTelemetry für verteiltes Tracing instrumentiert werden:
- **OTEL Collector:** `signoz-otel-collector.platform.svc.cluster.local:4317`
- **Metrikexport:** Automatisch über Java-Agent

## Fehlerbehebung

### Dienst startet nicht
```bash
# Check pod status
kubectl get pods -n caritas | grep <service-name>

# Check logs
kubectl logs -n caritas deployment/oriso-platform-<service-name> --tail=100

# Check events
kubectl describe pod -n caritas <pod-name>
```

### Probleme mit Datenbankverbindungen
```bash
# Verify database is accessible
kubectl exec -n caritas deployment/oriso-platform-<service-name> -- \
  curl http://oriso-platform-mariadb.caritas.svc.cluster.local:3306

# Check database credentials
kubectl get secret mariadb-secrets -n caritas -o yaml
```

### Kommunikationsprobleme zwischen Diensten
```bash
# Test service DNS resolution
kubectl exec -n caritas deployment/oriso-platform-<service-name> -- \
  nslookup oriso-platform-userservice.caritas.svc.cluster.local

# Test HTTP connectivity
kubectl exec -n caritas deployment/oriso-platform-<service-name> -- \
  curl http://oriso-platform-userservice.caritas.svc.cluster.local:8082/actuator/health
```
