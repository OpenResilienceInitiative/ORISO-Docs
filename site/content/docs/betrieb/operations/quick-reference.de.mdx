# Kurzreferenz zum Nachschlagen

Kurzreferenz für wichtige Verwaltungsbefehle, Ports und Dateispeicherorte der ORISO-Plattform.

## Wichtige Befehle

### Helm-Vorgänge

Verwenden Sie für Installationen und Upgrades das aktuelle Umbrella-Chart aus ORISO-Helm. [Kubernetes-Deployment](/de/plattform/core-systems/kubernetes-deployment)

```bash
# Check Helm release
helm list -n caritas

# Check release status
helm status <release> -n <namespace>

# View release values
helm get values <release> -n <namespace>

# Rollback deployment
helm rollback <release> <revision> -n <namespace>
```

### Pod-Verwaltung

```bash
# Check all pods
kubectl get pods -n caritas

# Check pod logs
kubectl logs deployment/oriso-platform-<service> -n caritas

# Follow logs in real-time
kubectl logs deployment/oriso-platform-<service> -n caritas -f

# Restart deployment
kubectl rollout restart deployment/oriso-platform-<service> -n caritas

# Check rollout status
kubectl rollout status deployment/oriso-platform-<service> -n caritas

# Scale deployment
kubectl scale deployment/oriso-platform-<service> --replicas=2 -n caritas
```

### Dienstverwaltung

```bash
# Check all services
kubectl get svc -n caritas

# Check service endpoints
kubectl get endpoints -n caritas <service-name>

# Port forward for local access
kubectl port-forward -n caritas svc/<service> <local-port>:<service-port>
```

### Fehlersuche

```bash
# Execute command in pod
kubectl exec -it deployment/<name> -n caritas -- /bin/bash

# Check pod events
kubectl describe pod <pod-name> -n caritas

# Check all events (sorted by time)
kubectl get events -n caritas --sort-by='.lastTimestamp'

# Check resource usage
kubectl top pod <pod-name> -n caritas
kubectl top nodes
```

### Zustandsprüfungen

```bash
# Check service health
curl http://127.0.0.1:<port>/actuator/health

# Check detailed health
curl http://127.0.0.1:<port>/actuator/health/db | jq .
curl http://127.0.0.1:<port>/actuator/health/redis | jq .
```

## Wichtige Dateien

### Konfigurationsdateien

- Helm-Chart und Ingress liegen in ORISO-Helm. [Kubernetes-Deployment](/de/plattform/core-systems/kubernetes-deployment)
- SQL-Initialisierung und Service-Migrationen haben getrennte Quellen. [Datenbanken einrichten](/de/betrieb/deployment/setup-databases)
- Realm und Clients werden über das Keycloak-Subchart verwaltet. [Keycloak konfigurieren](/de/betrieb/deployment/configure-keycloak)
- Kubeconfig: `~/.kube/config`
- k3s-Konfiguration: `/etc/rancher/k3s/k3s.yaml`

### Konfigurationszugriff

```bash
# View Nginx config
kubectl get configmap oriso-nginx-config -n caritas -o yaml

# View deployment configuration
kubectl get deployment <name> -n caritas -o yaml

# View service configuration
kubectl get svc <name> -n caritas -o yaml
```

## Skript zur schnellen Zustandsprüfung

Prüfen Sie die lokalen Dienste, die die unten gezeigten Ports verwenden. Für eine bereitgestellte Umgebung prüfen Sie den öffentlichen HTTPS-Issuer. [Keycloak konfigurieren](/de/betrieb/deployment/configure-keycloak)

```bash
#!/bin/bash
echo "Checking ORISO Platform Services..."

# Backend Services
for port in 8081 8082 8083 8084; do
  echo -n "Port $port: "
  curl -s http://127.0.0.1:$port/actuator/health | jq -r '.status' || echo "FAILED"
done

# Frontend
echo -n "Frontend (9001): "
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:9001

# Admin
echo -n "Admin (9002): "
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:9002

echo "Health check complete!"
```

## Häufige Befehle zur Fehlerbehebung

```bash
# Check all pods status
kubectl get pods -n caritas

# Check failing pods
kubectl get pods -n caritas | grep -v Running | grep -v Completed

# Check pod logs with errors
kubectl logs deployment/<name> -n caritas --tail=100 | grep -i error

# Check resource limits
kubectl describe nodes

# Check persistent volumes
kubectl get pvc -n caritas

# Check events for errors
kubectl get events -n caritas --field-selector type=Warning
```
