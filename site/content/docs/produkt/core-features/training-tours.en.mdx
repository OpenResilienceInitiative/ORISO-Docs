New counsellors should not learn the platform on real people. ORISO offers two kinds of help: tours
that point out where things are, and a practice area in which counsellors try the main steps on
practice cases. Nothing done in the practice area leaves the counsellor's own browser, so mistakes
cost nothing.

This page describes **what** the feature does. It is written for counsellors and heads of
Beratungsstellen who onboard new colleagues.

## 4.15.1 What you can do with it

- **Find your way** with an overview tour of the counselling interface.
- **Switch to e-mail counselling** with a tour that shows what is different there.
- **Practise "accept an enquiry"** step by step: accept a practice enquiry and answer it.
- **Practise "bring in supervision"**: add a supervisor to an accepted practice case.
- **Try things without risk** in the practice area, on practice cases instead of real people.

## 4.15.2 The four tours

| Tour | What it shows |
|---|---|
| **Overview** | five steps: introduction, enquiries, my conversations, archive, profile |
| **E-mail counselling** | what is new, enquiries, accepting, my conversations, writing, archive |
| **Practice: accept an enquiry** | accepting a practice enquiry and answering it |
| **Practice: bring in supervision** | adding a supervisor to an accepted practice case |

A tour can be restarted at any time from the help area of the profile. ORISO remembers on the server
which tours a counsellor has finished, together with the version of each tour.

## 4.15.3 Why nothing can go wrong in the practice area

- **Nothing is sent.** In practice mode, the app blocks every request that would change something on
  the server. Only reading is allowed, plus saving the tour progress.
- **Nothing is kept.** Practice cases live in the browser's memory only and disappear when the
  practice ends.
- **Nothing can be confused.** Practice cases carry identifiers that can never belong to a real
  case, and a banner shows that practice mode is on.

## 4.15.4 Who decides

The platform operator switches tours on or off for the platform. The practice area is switched on
per installation (release switch `enablePracticeArea`); it is off until it has been proven on the
development system.
