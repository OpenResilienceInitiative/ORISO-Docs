## 4.5.1 Was Gruppenchats sind

Ein **Gruppenchat** ist ein Matrix-Raum mit **mindestens zwei Mitgliedern beliebiger Rolle**, optional einschließlich Ratsuchender. Gruppenchats erfüllen vier praktische Bedürfnisse:

| Gruppentyp | Beispielbezeichnung | Mitglieder | Zweck |
|---|---|---|---|
| **Teamberatung** | *Teamberatung*, *Team Intern* | nur Beratende | Interne Fallbesprechung. |
| **Selbsthilfe / Runde** | *Supportgruppe Alkohol*, *Montagstreffen Kreuzbund*, *Gesprächsrunde Trauerhilfe* | viele Ratsuchende und ein bis zwei Beratende als Moderation | Gruppenberatung zu gemeinsamem Thema. |
| **Familienberatung** | *Familienberatung* | einige zusammengehörige Ratsuchende und Beratungsperson | Gespräch mit mehreren Beteiligten und nahestehenden Personen. |
| **Interne Verwaltung** | *Träger Admins Caritas* | Administration / Supervision | Betriebliche Abstimmung. |

In Figma sichtbare Unterformen: `Lokal 1:1`, `Live 1:1`, `Kreis` (Gesprächskreis), `Intern`, `Fachblick`, `Trauerhilfe`. Dies sind **Bezeichnungen auf derselben zugrunde liegenden Gruppenchat-Funktion**, die zum Filtern und Weiterleiten dienen — keine getrennten technischen Typen.

## 4.5.2 Wie ein Gruppenchat entsteht

Zwei Wege:

1. **Bestehendes Einzelgespräch erweitern** — Beratende klicken in einem aktiven Raum auf **Weitere Personen einladen** (`⇧I`) im Menü Chatraum-Einstellungen. Alle durch die Verwaltungsrichtlinie erlaubten Personen können eingeladen werden. Der Raum wird zur Gruppe; Ratsuchende erhalten eine Systemnachricht und werden je Trägerrichtlinie gegebenenfalls erneut um Einwilligung gebeten.
2. **Direkte Erstellung** — `Erstelle Chat` öffnet die Teilnehmerauswahl (`Add` → Suche → Mehrfachauswahl). Die erstellende Person wählt eine Chat-Typ-Bezeichnung, optional Supervision und optional einen Termin (`live Mo 9.Sep 2026 um 18:00 Uhr`).

## 4.5.3 Mitgliedsrollen innerhalb einer Gruppe

| Rolle im Raum | Ursprung | Möglichkeiten |
|---|---|---|
| **Eigentümer / Ersteller** | Beratende, die den Raum erstellt oder erweitert haben | Einladen, archivieren, stummschalten, Nachrichten löschen, Supervision einstellen, zusammenfassen |
| **Beratende (Moderation)** | Eingeladene Beratende | An alle / Teilmenge senden (mehrere Empfänger), im Thread antworten, markieren/unkenntlich machen, weiterleiten, zusammenfassen |
| **Supervision** | Beratende mit `supervisor-consultant`-Kennzeichnung, eingeladen oder automatisch zugeordnet | Nur lesend oder volle Teilnahme je Einstellung; erscheint mit Systembanner |
| **Ratsuchende** | Anonyme Keycloak-Person | Nachrichten senden; im Thread antworten *wenn Administration erlaubt*; **kein** Versand an mehrere Empfänger, Markieren/Unkenntlichmachen, Zusammenfassen, Übergeben oder Eskalieren |

Werkzeuge nur für Beratende werden in der Oberfläche für Ratsuchende ausgeblendet **und** von der API zurückgewiesen, als mehrschichtige Schutzmaßnahme.

## 4.5.4 Versand an mehrere Empfänger („Wähle wer diese Nachricht sehen soll“)

Das neuartigste Werkzeug zur Zusammenarbeit. Beratende können eine einzelne Nachricht an eine **Teilmenge** des Raums richten.

### Regeln der Senden-Schaltfläche (in Figma bestätigt)

| Bedingung | Verhalten |
|---|---|
| **A** Raum hat nur zwei Teilnehmende (Einzelgespräch) | Mehrfach-Empfänger-Schaltfläche vollständig ausblenden. |
| **B** Raum hat mehr als zwei Teilnehmende | Graue Schaltfläche zeigen (Standardzustand). |
| **B2** Berührungsbereiche | Nach AAA zugängliche Berührungsflächen bereitstellen. |
| **C** Symbol | Chat-Typ-Symbol verwenden (Personen/Gruppe), kein allgemeines Personensymbol. |
| **D** Erinnerung | Letzte Auswahl je Chat merken. |
| **E** Sichtbarkeit für Ratsuchende | Für Ratsuchende **immer ausgeblendet**. |

### Empfängerauswahl

Die Auswahl zeigt:
- Flache Liste der Raum-Mitglieder mit Auswahlkästchen.
- Schnellauswahl: `Select All`, `Select All Counsellors`, `Select All Moderators`.
- Live-Ergebniskennzeichnung: *„nur sichtbar für: Ich“*, *„3 Moderierende“*, *„+23“* usw.
- Ein Schalter „Direkt antworten“ / „Im Thread antworten“ steuert das Ziel.

### Tatsächlicher Ablauf (vorgeschlagen)

Matrix hat keine native Einschränkung einzelner Nachrichten auf „nur für N Mitglieder sichtbar“. Daher schlagen wir einen **serverseitigen Relay-Dienst** vor (Dienstkonto „Carimat-relay“):

### Statuskennzeichnungen

Nach dem Senden zeigt die Nachricht im Chat eine Kennzeichnung, die ihre Sichtbarkeit erklärt:

| Kennzeichnung | Bedeutung |
|---|---|
| *nur sichtbar für: Ich* | Eigene Notiz / im Thread gespeicherter Entwurf |
| *nur sichtbar für: 3 Moderierende* | Für diese drei Personen und den Absender sichtbar |
| *nur sichtbar für: 0 Beratende / 1 Ratsuchende Person* | Nur für die genannte ratsuchende Person sichtbar |
| *(keine Kennzeichnung)* | Für den gesamten Raum sichtbar (Standard) |

## 4.5.5 Direkt oder im Thread antworten

Der Eingabebereich bietet vier Sendemodi:

1. **Direkt senden** — Haupt-Thread, alle Mitglieder.
2. **Direkt antworten** — übergeordnete Nachricht zitieren, Haupt-Thread.
3. **Im Thread antworten** — Neben-Thread zur übergeordneten Nachricht öffnen / fortsetzen.
4. **Mehrere Empfänger** — jeden der obigen Wege auf eine Teilmenge begrenzen.

UX-Regel: *„Wichtig. Wenn ich erneut ins Textfeld klicke, sendet der Klick auf Senden dieses Element nur direkt entweder in den Thread oder Editor.“* — Sobald ein Thread geöffnet ist, geht die nächste Sendung dorthin, bis ausdrücklich zurückgeschaltet wird.

## 4.5.6 Weiterleiten und Löschen

- **Nachricht weiterleiten** — öffnet eine Empfängerauswahl ähnlich dem Mehrfachversand; sendet eine Kopie mit ursprünglichem Zeitstempel. Weiterleitungen sind ebenfalls nur Beratenden erlaubt.
- **Nachricht löschen** — Matrix-Redaktionsereignis; als Platzhalter „Nachricht gelöscht“ sichtbar.

## 4.5.7 Datei-Upload

- Text im Ablegebereich: *„Ziehen Sie die Datei in das Feld, um sie hochzuladen.“*
- Erlaubt: `.jpg, .png, .pdf, .docx, .xlsx`.
- Höchstens **10 MB** je Datei.
- Im Matrix-Medienspeicher abgelegt, bei Speicherung verschlüsselt.

## 4.5.8 Gruppenchat-Einstellungen („Chatraum Einstellungen“)

| Eintrag | Kürzel | Wirkung |
|---|---|---|
| **Archiviere Chat** | `⇧A` | Archivieren; Chat wird inaktiv und nach **zwölf Monaten** automatisch gelöscht (laut Figma-Text: *„Archivierte Benachrichtigungen sind inaktiv. Der Chat wird in 12 Monaten gelöscht.“*) |
| **Stummschalten** | `⇧Ö` | Benachrichtigungen nur für diesen Chat stummschalten. |
| **Hilfe Anfragen** | `⇧Ä` | Interne/externe Eskalation — siehe [Benachrichtigungen und Hilfsanfragen](/de/produkt/core-features/notifications). |
| **Weitere Personen einladen** | `⇧I` | Weitere Teilnehmende einladen. Durch Verwaltungsrichtlinie begrenzt. |
| **Supervision an / aus** | `⇧I` (Figma) | Sichtbarkeit der Supervision umschalten; Systemnachricht an alle. |
| **Chat Zusammenfassen** | `⇧Ü` | KI-Zusammenfassung — siehe [KI-Werkzeuge](/de/produkt/core-features/ai-tools). |

## 4.5.9 Filter, Phasen und Listenansichten

Die Chat-Liste sortiert und filtert jetzt nach mehreren Dimensionen. Tabs oben im Eingang der Beratenden:

`Ungelesen` · `1-1 Beratung` · `Live-Chat` · `Gruppen` · `Aktiv` · `Termine` · `Archiv` · `Anfragen`

Filterkennzeichnungen (in der Leiste sichtbar): `Personen`, `Type`, `Beratungsstelle`, `Archived`. Dazu die weiteren Tabs: `Gespräche`, `Reports`, `Mein Profil`, `Logs`, `Entwürfe` (Entwürfe), `Aktivität` (Aktivität), `Zeitstrahl` (Zeitstrahl), `Gemerkt` (angeheftet), `Terminiert` (geplant).

### Phasenmodell (Eingang der Beratenden)

Jeder Listeneintrag zeigt die Phase des Chats:

| Phase | Bedeutung |
|---|---|
| **Anfragephase** | Anfrage/Ticket erstellt, noch keine Annahme durch Beratende. |
| **Vermittlungsphase** | Beratende haben angenommen, Raum aber noch nicht fertiggestellt — umfasst ausstehende DSGVO-Einwilligung Nr. 2 und ausstehende Übergabe. |
| **Aktiv** | Beide Einwilligungen erteilt, Gespräch läuft. |
| **Archiv / Terminiert** | Vergangene oder geplante Gespräche. |

## 4.5.10 Lebenszyklus und Aufbewahrung

| Ereignis | Verhalten |
|---|---|
| **Mitglied verlässt Gruppe** | Pseudonym sofort gelöscht; verfasste Nachrichten bleiben im Raum mit Autorenbezeichnung *„Ehemaliger Teilnehmer“* (E2EE-Inhalte sind keine personenbezogenen Daten). |
| **Letzte ratsuchende Person geht** | Raum automatisch archiviert; Beratende per Systemnachricht informiert. |
| **Beratungsperson verlässt Gruppe** | Ihr Platz wird frei; war sie die einzige, erfordert der Raum Aufmerksamkeit der Administration. |
| **Gruppe archiviert** | Nur lesend; nach zwölf Monaten automatisch gelöscht, sofern nicht wiederhergestellt. |
| **Gruppe beendet** | Raum-Tombstone; Nachrichten nach 48 Stunden gelöscht (Standardregel). |

## 4.5.11 Sonderfälle (gruppenchatspezifisch)

Der vollständige Katalog steht unter [Sonderfälle](/de/produkt/design-und-quality/edge-cases). Wichtige Gruppenfälle:

- **Ratsuchende löschen sich während Gruppenchat** → siehe [9.1.8](/de/produkt/design-und-quality/edge-cases#918-client-deletes-self-from-group-chat).
- **Mehrfachversand an offline befindliche Empfänger** → Nachricht zugestellt, sobald deren Megolm-Sitzung wieder online ist; niemals für andere sichtbar.
- **Beratende laden nicht erlaubte Person ein** → API liefert 403 mit dem Grund aus der Verwaltungsrichtlinie.
- **Administration deaktiviert Gruppenchats global** → Bestehende Gruppen nur noch lesend; keine neuen Gruppen möglich; kein Datenverlust.
