## 8.1 Referenzdiagramm

Das Diagramm zeigt drei Dinge gemeinsam:

1. **Oben rechts:** Rollenhierarchie (Plattform-Admin → Träger-Admin → Beratungsstellen-Admin → Beratende) mit **MFA verpflichtend** bei Plattform-/Träger-Admins und Dokumenten **Impressum / Datenrichtlinie / DSGVO-Vereinbarung** an jeder Ebene.
2. **Mitte:** Vererbung von Rechtstexten entlang des Baums (durchgezogene Pfeile = erstellen, gestrichelte = erben / Rückfall) in **Beratungsstellen** und von dort in den Live-Chat-Ticketablauf.

Die sichtbaren Bildschirme folgen unten in der Reihenfolge, in der Ratsuchende oder Mitarbeitende sie erleben.

## 8.2 Bildschirme

### 8.2.1 Öffentlicher Live-Chat-Einstieg → Warteraum (Ratsuchende, mobil)

> Das Telefon unten links. Deutsche Bezeichnung: *Warteraum*.

| Aspekt | Detail |
|---|---|
| **Bildschirmname** | Warteraum — vor Einwilligung |
| **Zielgruppe** | Anonyme Ratsuchende, vorrangig mobil |
| **Zweck** | Erste DSGVO-Einwilligung erfassen und Ratsuchende in Warteschlange aufnehmen. |
| **Bestandteile** | Kopf *Warteraum* mit Zeitmesser; Pseudonymblock (*„DEIN PSEUDONYM — geschmeidiges Kanninchen Kim“*); Erklärung („Hallo, bevor wir fortfahren, bestätigen Sie bitte für diese Sitzung unserer auflagig diagnostizen Benutzerinnen…“); animierter Katzenavatar; unterer Dialog mit „Bestätigen“ sowie Sprach-/App-Rastersymbolen. |
| **Aktionen** | Einwilligungstext lesen → **Bestätigen** antippen für Plattformstandard. Optional Sprachglobus für Sprachwechsel antippen. |
| **Backend** | Beim Eintritt: `POST /live-chat/anonymous` liefert Ticket-ID und Cookie. Bei Bestätigung: `POST /live-chat/consent?level=platform` erfasst Einwilligung. Frontend wechselt in Wartestatus. |
| **Hinweise / Regeln** | Pseudonym deterministisch aus Zufall erzeugt, nie wiederverwendet. Beim ersten Anzeigen **Browsersprache** verwenden (englischer Rückfall, *nicht* Deutsch). |

### 8.2.2 Warteraum — in Warteschlange (Ratsuchende, mobil)

> Rechtes Telefon im Diagramm.

| Aspekt | Detail |
|---|---|
| **Bildschirmname** | Warteraum — wartend |
| **Zielgruppe** | Anonyme Ratsuchende |
| **Zweck** | Während Wartezeit beruhigen, E2EE-Garantie zeigen, eigenständige Zuordnungsänderungen erlauben. |
| **Bestandteile** | Datenschutzbanner (*„Vielen Dank, übrigens zum Schutz Ihrer Privatsphäre sind alle Nachrichten Ende-zu-Ende verschlüsselt und werden noch nach 48 Stunden automatisch gelöscht.“*); Emoji-Atemspiel; Zähler **„23 Noch vor Ihnen“**; „Vor Ort Beratungsanfrage absenden“ (stattdessen persönliche Beratung anfragen); Link *Spiel zu warten*. |
| **Aktionen** | Warten. Optional Atemanimation spielen, zu Anfrage wechseln oder abbrechen (Tab schließen → Löschung). |
| **Backend** | Regelmäßiger Heartbeat an `POST /sessions/&#123;id&#125;/heartbeat` (oder WS); Position über Redis; Übernahmebenachrichtigung via Redis Pub/Sub. |
| **Hinweise / Regeln** | Zähler muss **live** sein (Pub/Sub-Ereignisse, kein Polling). Aufbewahrungstext (48 Stunden) muss eingehalten werden — öffentliche Zusage. |

### 8.2.3 DSGVO-Einwilligung Nr. 2 (Ratsuchende, mobil, Vollbild)

> Durch mittleren Knoten *„Ratsuchende müssen DSGVO der Beratungsstelle zustimmen“* angedeutet.

| Aspekt | Detail |
|---|---|
| **Bildschirmname** | DSGVO-Einwilligung der Beratungsstelle |
| **Zielgruppe** | Anonyme Ratsuchende bei Annahme ihres Tickets |
| **Zweck** | **Beratungsstellenspezifische** Vereinbarung vor Öffnung des Chats einholen. |
| **Bestandteile** | Vollbildfläche; zentriertes „Einverstanden“ / „Bestätigen“; „Ablehnen“-Link; Stellenname und Impressumsauszug. |
| **Aktionen** | Lesen; **Bestätigen** (Chat öffnet) oder **Ablehnen** (Sitzung abgebrochen, Pseudonym gelöscht). |
| **Backend** | `POST /live-chat/consent?level=center`. Annahme: Ticket → `Active`, Matrix-Raum fertiggestellt. Ablehnung: Ticket → `Abandoned`, anonyme Person gelöscht. |
| **Hinweise / Regeln** | Einwilligung **nicht überspringbar**. Auch nach Plattformeinwilligung im Warteraum ist diese *zusätzliche* Einwilligung erforderlich. |

### 8.2.4 Live-Chat (Ratsuchende, mobil)

|---|---|

## 8.3 Bildschirmübergreifende Interaktionsmuster

### 8.3.1 Zwei unterschiedliche DSGVO-Abfragen

Häufige Verwechslung: Warteraum-Popup ist **Plattformebene**, Popup bei Übernahme **Beratungsstellenebene**. Visuell sollten sie **unterscheidbar** sein (andere Überschriften, andere „bereitgestellt von …“-Fußzeilen).

### 8.3.2 Deaktivierter Zustand muss informieren

Ausgeschalteter Live-Chat zeigt:
- Ausgegraute Ticketliste.
- Banner *„Live-Chat ist derzeit ausgeschaltet. Aktivieren Sie ihn, um Anfragen zu erhalten.“* mit Aufruf zum Aktivierungsschalter.
- Dieselbe Zahl historischer Tickets (nur lesend) als Kontext.

### 8.3.3 Alter Anfragebereich bleibt erhalten

Älterer Anfrage-Chat (PLZ-basiert, registriert) besteht **neben** Live-Chat auf dem Dashboard — gemeinsame Navigation, getrennte Bereiche.

### 8.3.4 Mobil zuerst

Warteraum und Live-Chat für Mobilgeräte entworfen (Figma: iPhone 15 Pro). Adminbereich für Desktop (Datentabellen, mehrere Spalten).

## 8.4 Offene Gestaltungstickets (aus Gespräch)

- **Live-Chat-Einstieg neu gestalten** — Atemspiel-/Warteraumablauf halb fertig; abschließen. *(Ticket: „fix live chat onboarding screen design“.)*
- **Live-Chat-Linkerstellung** — überkompliziert; auf „eine Schaltfläche je Thema je Stelle“ vereinfachen.
- **Zweisprachige Oberfläche** — alle Bildschirme parallel EN/DE, Browsersprache mit englischem Rückfall.
- **Gestaltungssystem angleichen** — sichtbare Abweichungen des Adminbereichs von Figma; Refactoring-Backlog.
- **Entfernte Bereiche sichtbar deaktivieren, nicht verstecken** — globale Regel.

## 8.7 Regeln für Animation und Mikrointeraktion (übernommen)

Aus Figma-Anmerkungen übernimmt ORISO global:

- Animationen **einmal** je Klick; niemals Schleife.
- Wiedergabegeschwindigkeit **≤ 0,7×**.
- Leere Zustände verwenden appweit dieselben neutralen kleinen Illustrationen.
- Hover-Zustand immer vorhanden (keine ausschließlich darauf beruhenden Interaktionen, aber immer visueller Hinweis).
- Schaltflächencontainer merkt sich letzten offenen/geschlossenen Zustand je Person.
