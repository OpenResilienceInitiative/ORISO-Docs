# Überprüfung und Tests

Umfassende Testanleitung zur Überprüfung, ob die ORISO-Plattform v3.0.0 auf Kubernetes korrekt funktioniert.

<Steps>
<Step title="Kubernetes-Bereitstellung prüfen">

Prüfen Sie alle Pods, Dienste und den Status der Helm-Release.

```bash
# Check all pods
kubectl get pods -n caritas

# Check Helm release
helm list -n caritas
helm status oriso-platform -n caritas

# Check services
kubectl get svc -n caritas

# Check Ingress
kubectl get ingress -n caritas

# Check TLS certificates
kubectl get certificate -n caritas

# Count running pods
kubectl get pods -n caritas --no-headers | grep Running | wc -l
# Should be 20+ pods
```

<Check>
- Alle Pods sollten `Running` sein.
- Die Helm-Release sollte den Status `deployed` anzeigen.
- Dienste sollten mit dem Präfix `oriso-platform-*` erstellt sein.
- Ingress-Ressourcen sollten erstellt sein.
- Zertifikate sollten `Ready=True` sein.
</Check>

</Step>

<Step title="Zustandsendpunkte der Dienste testen">

Testen Sie die Zustandsendpunkte aller Backend-Dienste.

```bash
# Test via Ingress (external)
curl -s https://api.example.org/actuator/health | jq .

# Or test internally
kubectl exec -n caritas deployment/oriso-platform-userservice -- \
  curl -s http://localhost:8082/actuator/health

# Test all backend services
for service in tenantservice userservice consultingtypeservice agencyservice; do
  echo "Testing $service..."
  kubectl exec -n caritas deployment/oriso-platform-$service -- \
    curl -s http://localhost:808*/actuator/health | jq .status
done
```

<Check>
Alle Dienste sollten `{"status":"UP"}` oder ausführliche Zustandsinformationen zurückgeben.
</Check>

</Step>

<Step title="Frontend-Zugriff testen">

Prüfen Sie, ob Frontend-Anwendungen über Ingress erreichbar sind.

```bash
# Test Frontend
curl -I https://app.example.org

# Test Admin
curl -I https://admin.example.org

# Check Ingress routing
kubectl describe ingress -n caritas | grep -A 5 "app.example.org"
```

<Check>
Beide Endpunkte sollten HTTP 200 OK zurückgeben.
</Check>

</Step>

<Step title="Authentifizierungsablauf testen">

Prüfen Sie, ob die Keycloak-Authentifizierung funktioniert.

```bash
# Test Keycloak realm discovery
curl -s https://auth.example.org/realms/online-beratung/.well-known/openid-configuration | jq .realm

# Test token endpoint
curl -X POST "https://auth.example.org/realms/online-beratung/protocol/openid-connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=app" \
  -d "username=testuser" \
  -d "password=testpass" \
  -d "grant_type=password" | jq .
```

<Check>
- Realm-Erkennung sollte `"online-beratung"` zurückgeben.
- Der Token-Endpunkt sollte access_token und refresh_token zurückgeben.
</Check>

</Step>

<Step title="Backend API testen">

Testen Sie Backend-API-Endpunkte mit Authentifizierung.

```bash
# Get access token first
ACCESS_TOKEN=$(curl -s -X POST "https://auth.example.org/realms/online-beratung/protocol/openid-connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "client_id=app" \
  -d "username=testuser" \
  -d "password=testpass" \
  -d "grant_type=password" | jq -r .access_token)

# Test API endpoints via Ingress
curl -H "Authorization: Bearer $ACCESS_TOKEN" \
  https://api.example.org/api/tenants | jq .

curl -H "Authorization: Bearer $ACCESS_TOKEN" \
  https://api.example.org/api/users/data | jq .
```

<Check>
APIs sollten JSON-Daten mit dem Status HTTP 200 OK zurückgeben.
</Check>

</Step>

<Step title="Matrix-Chat testen">

Prüfen Sie, ob Matrix Synapse betriebsbereit ist.

```bash
# Test Matrix API
curl -s https://matrix.example.org/_matrix/client/versions | jq .

# Test Matrix discovery
curl -s http://YOUR_SERVER_IP/.well-known/matrix/server | jq .

# Test Matrix federation
curl -s http://YOUR_SERVER_IP:8009/_matrix/federation/v1/version | jq .
```

<Check>
- Die Matrix API sollte Versionsinformationen zurückgeben.
- Discovery sollte die Serverkonfiguration zurückgeben.
- Die Föderations-API sollte antworten.
</Check>

</Step>

<Step title="Datenbankverbindung testen">

Prüfen Sie, ob alle Dienste die Datenbanken erreichen können.

```bash
# Test MariaDB connection from service
kubectl exec -n caritas deployment/oriso-platform-userservice -- \
  env | grep DATASOURCE

# Test MariaDB directly
kubectl exec -n caritas deployment/oriso-platform-mariadb -- \
  mysql -u root -p${MYSQL_ROOT_PASSWORD} -e "SHOW DATABASES;"

# Test MongoDB
kubectl exec -n caritas deployment/oriso-platform-mongodb -- \
  mongosh --eval "show dbs"
```

<Check>
- Dienste sollten korrekte Datenbank-Verbindungszeichenfolgen haben.
- Datenbanken sollten erreichbar sein.
- Alle Datenbanken sollten aufgeführt sein.
</Check>

</Step>

<Step title="Dienstkommunikation testen">

Prüfen Sie, ob Dienste über Kubernetes-DNS kommunizieren können.

```bash
# Test UserService can reach TenantService
kubectl exec -n caritas deployment/oriso-platform-userservice -- \
  curl -s http://oriso-platform-tenantservice.caritas.svc.cluster.local:8081/actuator/health

# Test DNS resolution
kubectl run test-pod --rm -it --image=busybox -n caritas -- \
  nslookup oriso-platform-userservice.caritas.svc.cluster.local
```

<Check>
- Dienste sollten sich gegenseitig erreichen können.
- DNS-Auflösung sollte korrekt funktionieren.
</Check>

</Step>
</Steps>

## Vollständige Prüfliste

- [ ] Alle Pods laufen (`kubectl get pods -n caritas`).
- [ ] Helm-Release ist bereitgestellt (`helm status oriso-platform -n caritas`).
- [ ] Alle Dienste sind erstellt (`kubectl get svc -n caritas`).
- [ ] Ingress-Ressourcen sind erstellt (`kubectl get ingress -n caritas`).
- [ ] TLS-Zertifikate sind ausgestellt (`kubectl get certificate -n caritas`).
- [ ] Frontend ist erreichbar (`curl -I https://app.example.org`).
- [ ] Admin ist erreichbar (`curl -I https://admin.example.org`).
- [ ] API ist erreichbar (`curl -I https://api.example.org`).
- [ ] Keycloak ist erreichbar (`curl -I https://auth.example.org`).
- [ ] Matrix ist erreichbar (`curl -I https://matrix.example.org`).
- [ ] Zustandsendpunkte geben UP zurück (`curl https://api.example.org/actuator/health`).
- [ ] Authentifizierung funktioniert (Token-Endpunkt gibt Tokens zurück).
- [ ] Backend-APIs funktionieren (mit Authentifizierung).
- [ ] Datenbankverbindungen funktionieren (Dienste können sich verbinden).
- [ ] Dienstkommunikation funktioniert (DNS-Auflösung).

## Fehlerbehebung

### Pods laufen nicht
```bash
# Check pod status
kubectl describe pod -n caritas <pod-name>

# Check logs
kubectl logs -n caritas <pod-name>

# Check events
kubectl get events -n caritas --sort-by='.lastTimestamp'
```

### Dienste sind nicht erreichbar
```bash
# Check Ingress Controller
kubectl get pods -n ingress-nginx

# Check Ingress resources
kubectl describe ingress -n caritas

# Check DNS resolution
dig app.example.org
```

### Zustandsprüfungen schlagen fehl
```bash
# Check service logs
kubectl logs -n caritas deployment/oriso-platform-<service>

# Test health endpoint directly
kubectl exec -n caritas deployment/oriso-platform-<service> -- \
  curl http://localhost:808*/actuator/health
```
