# Überwachung bereitstellen

Stellen Sie Überwachungs- und Observability-Dienste für die ORISO-Plattform bereit. Die Überwachungskomponenten werden über Helm als Teil des übergeordneten Charts `oriso-platform` bereitgestellt.

<Info>
Überwachungskomponenten:
- **SignOZ** – Observability-Plattform (APM, Tracing, Metriken)
- **Health Dashboard** – Überwachung des Dienstzustands
- **Statusseite** – Öffentliche Statusseite
</Info>

<Steps>
<Step title="Überwachungsbereitstellung prüfen">

Überwachungsdienste sollten bereits über Helm bereitgestellt sein. Prüfen Sie, ob alle Komponenten laufen.

```bash
# Check monitoring pods
kubectl get pods -n caritas | grep -E "signoz|health|status"

# Check SignOZ (if deployed in platform namespace)
kubectl get pods -n platform | grep signoz

# Check Health Dashboard
kubectl get pods -n caritas | grep health-dashboard
```

<Check>
Überwachungs-Pods sollten laufen. Falls nicht, müssen sie möglicherweise in den Helm-Werten aktiviert werden.
</Check>

</Step>

<Step title="SignOZ bereitstellen (optional)">

Stellen Sie die SignOZ-Observability-Plattform mit Helm bereit.

<Info>
SignOZ bietet verteiltes Tracing, Metriken und Protokolle. Es wird im Namespace `platform` bereitgestellt.
</Info>

```bash
# Add SignOZ Helm repo
helm repo add signoz https://charts.signoz.io
helm repo update

# Create namespace
kubectl create namespace platform

# Install SignOZ
cd ~/online-beratung/caritas-workspace/ORISO-SignOZ
helm install signoz signoz/signoz \
  --namespace platform \
  --values signoz-values-current.yaml

# Wait for SignOZ (may take 5-10 minutes)
kubectl wait --for=condition=ready pod \
  -l app.kubernetes.io/instance=signoz \
  -n platform \
  --timeout=600s

# Get SignOZ URL
kubectl get svc -n platform signoz-frontend
```

<Check>
SignOZ-Pods sollten laufen. Zugriff unter http://91.99.219.182:3001
</Check>

</Step>

<Step title="Health Dashboard prüfen">

Das Health Dashboard überwacht alle Zustandsendpunkte der Dienste.

```bash
# Check Health Dashboard pod
kubectl get pods -n caritas | grep health-dashboard

# Check service
kubectl get svc -n caritas | grep health-dashboard

# Access Health Dashboard
curl -I http://91.99.219.182:9001
```

<Info>
Health Dashboard:
- **URL:** http://91.99.219.182:9001
- **Prüfungen:** Alle `/actuator/health`-Endpunkte alle 60 Sekunden
- **Dienst:** `oriso-platform-health-dashboard.caritas.svc.cluster.local:9001`
</Info>

</Step>

<Step title="Dienstüberwachung konfigurieren">

Konfigurieren Sie Dienste zum Exportieren von Metriken nach SignOZ (optional).

**Für Spring-Boot-Dienste:**

Fügen Sie der Dienstbereitstellung den OpenTelemetry-Java-Agent hinzu:

```yaml
# In Helm values or deployment
env:
- name: JAVA_TOOL_OPTIONS
  value: >-
    -javaagent:/opt/otel/opentelemetry-javaagent.jar
    -Dotel.service.name=userservice
    -Dotel.exporter.otlp.endpoint=http://signoz-otel-collector.platform.svc.cluster.local:4317
    -Dotel.exporter.otlp.protocol=grpc
```

**OpenTelemetry-Agent herunterladen:**

```bash
wget https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar
```

</Step>
</Steps>

## Überwachungskomponenten

### SignOZ
- **Namespace:** `platform`
- **Zugriff:** http://91.99.219.182:3001
- **Zugangsdaten**: Verwenden Sie das verwaltete Betreiber-Secret für die Zielumgebung; veröffentlichen Sie niemals Zugangswerte.
- **Komponenten:**
  - SignOZ Backend
  - ClickHouse (Zeitreihendatenbank)
  - OTEL Collector
- **Funktionen:**
  - Verteiltes Tracing
  - Erfassung von Metriken
  - Zusammenführung von Protokollen
  - APM-Dashboards

### Health Dashboard
- **Namespace:** `caritas`
- **Dienst:** `oriso-platform-health-dashboard`
- **Zugriff:** http://91.99.219.182:9001
- **Funktionen:**
  - Zustandsprüfungen in Echtzeit
  - Überwachung des Dienststatus
  - Historische Zustandsdaten
  - Manuelle Aktualisierung

### Statusseite
- **URL:** http://status.oriso.site
- **Zweck:** Öffentliche Statusseite
- **Funktionen:** Dienstverfügbarkeit, Meldung von Vorfällen

## Zugriffs-URLs

Nach der Bereitstellung greifen Sie auf die Überwachung zu unter:

- **SignOZ:** http://91.99.219.182:3001
- **Health Dashboard:** http://91.99.219.182:9001
- **Statusseite:** http://status.oriso.site

## Fehlerbehebung

### SignOZ startet nicht
```bash
# Check pods
kubectl get pods -n platform

# Check logs
kubectl logs -n platform -l app.kubernetes.io/instance=signoz

# Check resources
kubectl top pods -n platform
```

### Health Dashboard funktioniert nicht
```bash
# Check pod
kubectl get pods -n caritas | grep health-dashboard

# Check logs
kubectl logs -n caritas deployment/oriso-platform-health-dashboard

# Verify service endpoints are accessible
kubectl exec -n caritas deployment/oriso-platform-health-dashboard -- \
  curl http://oriso-platform-userservice.caritas.svc.cluster.local:8082/actuator/health
```

### Metriken erscheinen nicht in SignOZ
```bash
# Check OTEL collector
kubectl get pods -n platform | grep otel-collector

# Check collector logs
kubectl logs -n platform -l app=otel-collector

# Verify service has OpenTelemetry agent
kubectl exec -n caritas deployment/oriso-platform-userservice -- env | grep OTEL
```
