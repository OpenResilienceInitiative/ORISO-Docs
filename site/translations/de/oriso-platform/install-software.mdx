# Erforderliche Software installieren

Installieren Sie alle Softwarewerkzeuge, die für die Bereitstellung der ORISO-Plattform v3.0.0 erforderlich sind. Die Plattform nutzt Kubernetes (k3s) mit Helm-Charts zur Bereitstellung.

<Steps>
<Step title="Docker installieren">

Installieren Sie Docker zum Erstellen von Container-Images, falls erforderlich.

```bash
# Remove old versions
sudo apt remove -y docker docker-engine docker.io containerd runc

# Add Docker GPG key
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg

# Add Docker repository
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu \
  $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

# Install Docker
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# Add user to docker group
sudo usermod -aG docker $USER

# Apply group change (or logout/login)
newgrp docker

# Verify Docker installation
docker --version
docker compose version

# Test Docker
docker run hello-world
```

<Check>
Prüfen Sie Docker: `docker --version` und `docker compose version` sollten die installierten Versionen anzeigen. Der hello-world-Test sollte erfolgreich abgeschlossen werden.
</Check>

<Note>
Möglicherweise müssen Sie sich ab- und wieder anmelden, damit die Mitgliedschaft in der docker-Gruppe wirksam wird, oder `newgrp docker` verwenden.
</Note>

</Step>

<Step title="k3s installieren (leichtgewichtiges Kubernetes)">

Installieren Sie k3s, eine leichtgewichtige Kubernetes-Distribution für Bereitstellungen auf einem einzelnen Knoten.

```bash
# Install k3s
curl -sfL https://get.k3s.io | sh -

# Wait for k3s to be ready
sudo systemctl status k3s

# Make k3s accessible to non-root user
sudo chmod 644 /etc/rancher/k3s/k3s.yaml

# Setup kubeconfig for current user
mkdir -p ~/.kube
sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
sudo chown $USER:$USER ~/.kube/config

# Verify k3s installation
sudo k3s kubectl get nodes
```

<Check>
Die erwartete Ausgabe sollte Ihren Knoten mit Status `Ready` und den Rollen `control-plane,master` anzeigen:
```
NAME             STATUS   ROLES                  AGE   VERSION
oriso-platform   Ready    control-plane,master   1m    v1.x.x
```
</Check>

</Step>

<Step title="kubectl installieren">

Installieren Sie kubectl, das Kommandozeilenwerkzeug für Kubernetes.

```bash
# Install kubectl
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
sudo install -o root -g root -m 0755 kubectl /usr/local/bin/kubectl
rm kubectl

# Verify kubectl
kubectl version --client

# Test kubectl with k3s
kubectl get nodes
kubectl get pods --all-namespaces
```

<Check>
Prüfen Sie, ob kubectl eine Verbindung zu k3s herstellen kann: `kubectl get nodes` sollte Ihren Knoten anzeigen.
</Check>

</Step>

<Step title="Helm 3.x installieren">

Installieren Sie Helm 3.x zur Verwaltung von Kubernetes-Anwendungen. Helm ist für die Bereitstellung der ORISO-Plattform **ERFORDERLICH**.

```bash
# Install Helm 3.x
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash

# Verify Helm
helm version

# Add required Helm repos
helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
helm repo add signoz https://charts.signoz.io
helm repo update
```

<Check>
Prüfen Sie die Helm-Installation: `helm version` sollte Version 3.x.x anzeigen. Helm wird für die Bereitstellung des übergeordneten ORISO-Plattform-Charts benötigt.
</Check>

</Step>

<Step title="Nginx Ingress Controller installieren">

Installieren Sie den Nginx Ingress Controller für externen Zugriff auf Dienste.

```bash
# Install Nginx Ingress Controller
helm install ingress-nginx ingress-nginx/ingress-nginx \
  --namespace ingress-nginx \
  --create-namespace \
  --set controller.service.type=LoadBalancer

# Wait for Ingress Controller to be ready
kubectl wait --namespace ingress-nginx \
  --for=condition=ready pod \
  --selector=app.kubernetes.io/component=controller \
  --timeout=90s

# Verify
kubectl get pods -n ingress-nginx
```

<Check>
Prüfen Sie, ob der Ingress Controller läuft: `kubectl get pods -n ingress-nginx` sollte den Controller-Pod im Zustand `Running` anzeigen.
</Check>

</Step>

<Step title="Cert-Manager installieren">

Installieren Sie Cert-Manager zur automatischen Verwaltung von TLS-Zertifikaten mit Let's Encrypt.

```bash
# Install cert-manager
kubectl apply -f https://github.com/cert-manager/cert-manager/releases/download/v1.13.0/cert-manager.yaml

# Wait for cert-manager to be ready
kubectl wait --for=condition=ready pod \
  -l app.kubernetes.io/instance=cert-manager \
  -n cert-manager \
  --timeout=300s

# Verify
kubectl get pods -n cert-manager
```

<Check>
Prüfen Sie, ob cert-manager läuft: `kubectl get pods -n cert-manager` sollte die cert-manager-Pods im Zustand `Running` anzeigen.
</Check>

<Note>
Nach der Installation von cert-manager erstellen Sie im Schritt [Kubernetes einrichten](/oriso-platform/setup-kubernetes) einen ClusterIssuer.
</Note>

</Step>

<Step title="Weitere Werkzeuge installieren">

Installieren Sie Datenbank-Clients und Hilfswerkzeuge zur Verwaltung der ORISO-Plattform-Dienste.

```bash
# Install MySQL client (for MariaDB)
sudo apt install -y mysql-client

# Install MongoDB client
wget -qO - https://www.mongodb.org/static/pgp/server-6.0.asc | sudo apt-key add -
echo "deb [ arch=amd64,arm64 ] https://repo.mongodb.org/apt/ubuntu focal/mongodb-org/6.0 multiverse" | sudo tee /etc/apt/sources.list.d/mongodb-org-6.0.list
sudo apt update
sudo apt install -y mongodb-mongosh

# Install Redis client
sudo apt install -y redis-tools

# Install tree (useful for directory viewing)
sudo apt install -y tree
```

<Check>
Prüfen Sie, ob die Werkzeuge installiert sind:
- `mysql --version`
- `mongosh --version`
- `redis-cli --version`
</Check>

</Step>
</Steps>

## Überprüfung

Prüfen Sie nach Abschluss aller Installationsschritte, ob alle Werkzeuge funktionieren:

```bash
# Check Docker
docker --version && docker compose version

# Check Kubernetes
kubectl version --client
kubectl get nodes

# Check k3s service
sudo systemctl status k3s

# Check database clients
mysql --version
mongosh --version
redis-cli --version
```

## Fehlerbehebung

### k3s startet nicht

Prüfen Sie die k3s-Protokolle:

```bash
sudo journalctl -u k3s -f
```

Prüfen Sie, ob Swap deaktiviert ist (für k3s erforderlich):

```bash
free -h
```

### kubectl kann keine Verbindung herstellen

Prüfen Sie die kubeconfig:

```bash
cat ~/.kube/config
```

Prüfen Sie den k3s-API-Server:

```bash
sudo systemctl status k3s
```

### Docker meldet fehlende Berechtigung

Stellen Sie sicher, dass Sie Mitglied der docker-Gruppe sind:

```bash
groups | grep docker
```

Falls nicht, melden Sie sich ab und wieder an oder verwenden Sie:

```bash
newgrp docker
```
