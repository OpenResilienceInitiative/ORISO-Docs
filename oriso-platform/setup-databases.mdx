# Set up databases

Each backend service owns the MariaDB schema it writes. The service's Liquibase master is the authority for changes. [ORISO-Database](https://github.com/OpenResilienceInitiative/ORISO-Database) is an archived source of historical schema exports.

## Start with an empty database

For a disposable local installation, use the managed runner in [Install and run locally](/docs/platform/install-and-run-locally). It selects the development contexts and starts each service with its own changelog. For a clean operator installation, the [Helm MariaDB initialization](https://github.com/OpenResilienceInitiative/ORISO-Helm/blob/3646aecbf865c6869f7a35b2491a30312561e6f5/charts/mariadb/templates/mariadb-configmap-initsql.yaml) creates databases and grants when the volume is first initialized. Service migrations create and evolve the application tables. Check `global.enableLiquibase` and the resolved service configuration on the selected [chart revision](https://github.com/OpenResilienceInitiative/ORISO-Helm/blob/3646aecbf865c6869f7a35b2491a30312561e6f5/values.yaml.default). The setting can differ between a standalone service profile and a chart deployment.

The MariaDB schema files shipped with the chart are schema mirrors. [Database and data model](/docs/platform/database-and-data-model) describes the separate MongoDB and Matrix PostgreSQL stores and their owners.

## Upgrade or restore existing data

- For an upgrade, confirm a recovery point and the intended service versions. Apply the release through the [Kubernetes deployment path](/docs/platform/kubernetes-deployment). Confirm the expected changesets in `DATABASECHANGELOG`, the migration lock is released, and the service is ready. Keep already applied changesets intact.
- For a restore, first verify the backup in an isolated compatible instance. Use the [MariaDB restore runbook](https://github.com/OpenResilienceInitiative/ORISO-Helm/blob/3646aecbf865c6869f7a35b2491a30312561e6f5/runbooks/mariadb-isolated-restore.md) and the [backup and recovery guide](/oriso-platform/backup-configuration). Compare the restored schema inventory and application invariants with the expected backup results before considering a cutover.
