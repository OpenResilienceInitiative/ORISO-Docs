# Backup and recovery

Use the backup procedure and scope approved for the environment. Match the artifact to its backup job, target, and receipt. Record a separate restore result for each completed backup job.

MongoDB and Matrix PostgreSQL are separate stores. Confirm the deployed backup procedure and acceptance for each separately in the [data protection tracker](https://github.com/OpenResilienceInitiative/ORISO-Helm/issues/282). A MariaDB archive covers only the schemas in its receipt.

## Rehearse application data recovery

1. Identify the intended backup artifact and compare its ciphertext checksums with the receipt. Confirm key custody and retention with the operator.
2. Use an empty compatible MariaDB instance isolated from application traffic. Follow the runbook to verify all archives before importing the first schema.
3. Compare the restored schemas and agreed application invariants. Each schema dump has its own transaction, so explicitly check any required cross-schema consistency.
4. Record the backup run, database version, checksums and results without exporting application data. A production cutover follows the separate approved recovery decision.
