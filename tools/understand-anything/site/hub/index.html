Wie eine Funktion arbeitet — für Produkt, Qualitätssicherung und EntwicklungHow a function works — for product, quality assurance and engineering

Die Graphen beantworten „was tut diese Datei". Sie beantworten nicht „wie funktioniert die Fallübergabe". Dafür gibt es Feature-Seiten: eine Seite je Funktion, geschrieben aus dem Graphen, den Architekturentscheidungen und dem Quelltext — mit dem Stand der Entwicklung an jeder Stelle. The graphs answer "what does this file do". They do not answer "how does case handover work". That is what the feature pages are for: one page per function, written from the graph, the architecture decisions and the source — with the state of development marked at every step.

FrischeFreshness

Einmal am Tag, nachts, baut GitHub alle Graphen neu — aus dem Branch main, also aus dem Code, der ausgeliefert und abgenommen ist. Kurz danach holt diese Seite das Ergebnis ab. Was auf dev liegt und noch nicht veröffentlicht ist, steht folgerichtig noch nicht im Graphen — das ist Absicht. Datum und Zahlen oben kommen direkt aus dem zuletzt abgeholten Graphen. Once a day, at night, GitHub rebuilds every graph from the branch main — the code that has been released and accepted. Shortly after, this page picks up the result. Whatever sits on dev and has not been released yet is consequently not in the graph — by design. The date and numbers above come straight from the graph that was picked up last.

Die Feature-Seiten tragen ihren eigenen Stand: das Datum des Graphen, aus dem sie geschrieben wurden, und den Entwicklungsstand jeder beschriebenen Teilfunktion. The feature pages carry their own state: the date of the graph they were written from, and the development state of every part they describe.
