# UA remediation acceptance matrix

Developers must be able to identify the source behind a graph, distinguish reviewed statements from hints, and detect an incomplete refresh before using it to plan a change. This remediation addresses all twelve findings in the September 6 holistic audit's `04-understand-anything.md`. Local implementation and automated evidence are available; **the final installed PreDev candidate, complete fresh generation, and browser acceptance remain pending at this document's freeze**. Passing tests below does not mean that the remediation is deployed or that the represented application journeys work at runtime.

Delivery belongs to [ORISO-Docs issue 110](https://github.com/OpenResilienceInitiative/ORISO-Docs/issues/110). [PR 107](https://github.com/OpenResilienceInitiative/ORISO-Docs/pull/107) is a separate feature and is excluded from this acceptance scope. This matrix neither accepts its behavior nor requests that it be merged. Priorities retain the audit's proposals: UA-01/02 P1, UA-03–11 P2, UA-12 P3.

## Preserved work and source boundaries

The implementation imports the current PreDev tooling and recent enrichment work before repairing their trust contract. [The import ledger](imported-sources.json) records 42 original inputs and SHA-256 hashes: 18 enrichment files, six summary files, seven tour files, ten tooling scripts, and the Docs analysis policy. Its repository baseline is `6b8d69995205f78053831075e093e061e0eb0b53`; the recorded integration reference is `9f748ba567011905b2287dfac2bbb49198d8ba9c`. These references identify the starting material, not a claim that the final changes are committed or deployed. Ledger hashes describe imported bytes; intentionally repaired producer scripts will differ.

The seven recently discovered tours cover Admin, Docs, AgencyService, Frontend, UserService, TenantService, and ConsultingTypeService. Historical annotations are retained, ambiguous legacy references have an explicit quarantine disposition, and current trusted references reject ambiguity. Older summaries stay visible as dated unbound/stale orientation; original prose, claim status, and structural summaries remain available in metadata. They are not silently promoted to reviewed statements because a stable ID survived extraction. Existing platform parsing, matching, classification, and narrative work remains in the owned platform tree; the remediation adds evidence and schema checks around it. Generated sampled graph files are artifact-only and excluded from the source change. Platform tests use inline or temporary synthetic fixtures; they do not require a committed `platform/fixtures` graph dump.

The producer fetches every required source and analyzes detached snapshots. It preserves developer checkout files and HEAD. The consumer defaults to an external cache; legacy graph migration is explicit, backs up existing bytes, and resolves worktree Git paths. The imported Docs analysis policy is versioned and inventoried in the generation; unrelated machine-only exclusions are not inherited. The complete bundle requires 18 repository graphs and both aggregates. The platform retains its declared 17-repository input subset, excluding Kubernetes; the supergraph covers all 18. An honest subset is not relabeled as complete platform coverage.
